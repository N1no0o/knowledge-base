# 案例拆解 · 5 分 41 秒大屯山日出登山片

**一句话结论：一条 71 分钟的登山素材剪到 5 分 41 秒，真正的杠杆不是"第一版剪得多好"，而是"改一版有多便宜"——四版里三个关键改动全部不是艺术判断，而是量出来的缺陷：转场接点亮度掉到 0（三十几刀连成"一直眨眼"）、字幕秒数越界根本不显示（登顶的 payoff 直接消失）、纯画面段落里把同行者的闲聊当环境音保留了下来。它同时给出本库第一条"淡入淡出会毁掉硬切"的实测反例。**

> **样本准入核对**：成片 **5 分 41 秒（341 s）** ≥ 60 s ✓｜题材＝登山／徒步（摸黑冲大屯山南峰＋西峰看日出）✓｜B 组参数 **7 项，含 5 个数值型**（71 min、12.5:1、69 支、四版时长、1.8 px、−24/−4~−8 dB）✓｜**缺项：成片镜数、镜长均值/分布、切点总数、刀/分**（原文未给，本页不推算、不补造）。

## 二、七条可迁移手法

1. **先把 69 支素材全部转成逐字稿，挑完句子再定剪点。**
   作者原话："我把 69 支的完整音訊全部轉成逐字稿，人工挑出連貫、有記憶點的句子，其餘丟掉"；"**先聽完所有對話再決定剪點**，故事就從嘴砲裡長出來了"。
   ⇒ 这是"剪气口"的**前置工序**：不是在对齐句子边界（那是切点微调），而是先在文本层决定"保留哪几句"，画面再跟着句子走。71 分钟的录音"八成是廢話"（头灯多少钱、谁离婚了、要不要吃炒冰）——**先删话，再删画面**，两条轴分开做。

2. **多版迭代的价值不在"改得好"，在"改一版足够便宜"。**
   v1 → v2 按量测修；v2 给家人看 → v3 加路线图、14 → 9.5 分钟；v3 再看 → v4 重挑素材、9.5 → 5 分 41 秒；v4 之后又为**一个音量细节**单独出一版。
   ⇒ 判定问句：**你的返工成本是"一晚上"还是"几分钟"？** 前者只能改三版就妥协，后者会为一条音量规则单独出片。

3. **review 要出数字，不能靠"看起来好多了"。**
   五项量测：抖动 / 字幕 / 转场 / 配乐 / 音量。三个例子：
   - 抖动：全片中位 **1.8 px**，只有绳索攀爬段真的晃（8 段 5.2 → 0.2 px）
   - 转场：**接点亮度掉到 0**，被定性为缺陷而不是风格
   - 音量：夜间段 **−24 dB** vs 对白段 **−4~−8 dB**，**差 16 dB** 才敢说"人声真的清干净了"
   ⇒ 没有数字的"改好了"不能算修完。这条与本库工程口径一致（判据 > 印象）。

4. **⚠️ 反例：每个接点都加淡入淡出 = 全片频闪。**
   v1 的做法是接点带转场，结果"**每個鏡頭接點的亮度都掉到 0，每一刀都閃一下黑。三十幾刀連在一起，像一直眨眼**"。
   v2 的修法：**全改硬切**，靠连续的 BGM 床衔接，"接點量測歸零"。
   ⇒ 这是本库第一次拿到"淡化转场破坏成片"的**实测反例**（详见第三节冲突表）。

5. **删的是"与主线无关的段"，不是把时长等比压缩。**
   v4 砍掉：口误、"送早餐"这类跟主线无关的段；补进：几个单人越野移动的镜头撑节奏；保留：山顶云海、台北盆地大展望做 highlight。
   ⇒ **先定"哪些段不成立"，再谈密度。** 从 9.5 分钟到 5 分 41 秒不是调速度，是**减段落**。

6. **人声/环境音的分界不是"有没有声音"，是"这段声音里的人在说主线吗"。**
   作者立了一条规则：**"没有字幕的段落——纯画面、移动、展望、环境——一律消音，只留音乐；人声只保留在有字幕的登山金句段。"**
   起因是家人一句："摸黑那段的對話跟登山根本無關，為什麼講話聲會被放進去？"
   ⇒ 12 段 b-roll 消音，人声只剩 8 段。**"环境音"要拆成"非语言环境声（脚步/风/溪流）"和"无关语言（闲聊）"两类**，前者保、后者必须消。

7. **举证层在徒步片里的实测形态：程序生成的海拔剖面 + 节点 + "你在这"光晕。**
   触发点是观众（家人）反馈"**資訊太少，看不出爬到哪了**"。做法：用程序画一张海拔剖面，每个节点插一张，金色光晕点出当前位置，"觀眾隨時知道爬到哪、還剩哪座"。
   ⇒ 它解决的是**空间定位**，不是"可信度"。成本极低（模板 + 元素时间轴），且不需要补拍。

## 三、与既有规则的冲突 / 修正

| 总纲原口径 | 本案数据 | 修正后口径 |
|---|---|---|
| "硬切是默认值，叠化是例外"（11-08：91 硬切 : 1 叠化；11-10：6/6 全硬切） | v1 每个接点带转场 → **接点亮度掉到 0**，三十几刀连成眨眼；v2 全改硬切后"接点量测归零" | **补强 + 加一条硬边界**：淡入淡出**只能用在"速度突变处"**（快进段进/出），**不能用在常规镜间切点**。40 刀 × 3 帧淡化 = 全片频闪，观众感知为"眨眼"不是"柔和" |
| （dv123 实操建议）快进段 >3 s 在入点出点各加 3 帧淡入淡出 | 本案把"接点淡化"整体判为缺陷 | **两条都要，但作用域不同**：3 帧淡化只包**变速段的进出**（一个片段最多 2 处），不包**镜与镜之间的每一刀**。二者混用就是频闪 |
| "保留环境音（脚步、风声、溪流）"（11-08 基线） | 本案把 12 段 b-roll 的人声**全部消掉**，人声只留 8 段 | **收窄定义**：保留的是**非语言环境声**；**无关语言（同行者闲聊）不算环境音**，必须消。判据＝这段环境音里的人有没有在讲主线 |
| "徒步片人声占比建议 35–45%"（11-09） | 本案人声只有 8 段，且全片大量段落到 −24 dB | 占比不是目标值，是**结果值**：先决定"哪 8 段值得留话"，占比自然落定。**不要为凑占比去留闲聊** |
| 举证层＝"可信的来源"（11-09，源自信息型访谈片） | 本案的举证层（海拔剖面）是**观众主动要的**，要的是"我在哪" | **功能拆分**：徒步片的举证层首先承担**空间定位/进度**，其次才是可信度。这也解释了 11-12 的"英里数播报"为何有效——同属定位类 |
| 压缩比由拍摄模式决定（11-12：脚本先行 86.5:1 / 事后拣选 10.9:1） | 本案 **12.5:1**（71 min → 5.68 min），事后拣选 + 四版迭代 | **补第三个点，且落在拣选型锚点内**（10.9 与 12.5 接近）。⇒ 拣选型的压缩比稳定在 **11–13:1**，与片长无关 |
| 密度-片长表（1–4 min → 15–25 刀/分） | 341 s 落在该区间，但**成片镜数未给**，无法核验 | **既非反证也非支持**，该格保持原状；不因本案调整 |

## 四、修正后的一句话规则（可证伪）

**镜与镜之间只允许硬切；3 帧淡入淡出只包"变速段的进/出"（一片段最多 2 处），不得包常规切点——否则 30 刀以上会连成频闪。**

判定方法：量每个切点的**前后帧平均亮度**，若接点亮度掉到接近 0（黑场），即判定为闪黑缺陷，不是"柔和过渡"。

## 五、置信度与边界（重要）

- **单一作者自述，非第三方逐镜拆解。** 镜数、镜长分布、切点总数、刀/分——四项硬缺口，本页全部留空，**不推算、不补造**。
- "三十几刀"原文未说明是**全片切点总数**还是**某一缺陷段的切点数**，本页不解读，也不据此反推刀/分。
- "五秒五秒的快剪"是作者对**摸黑段**的描述（约 5 s/段），不能当作全片均值。
- **71 分钟 / 69 支**由作者口述，压缩比按此计算；12.5:1 的误差随原始数字。
- **无播放量、无完播率。** 页面标注 282 views（发布后短期），**不构成效果证据**。唯一的效果信号是**定性反馈**（家人："太拖"、"看不出爬到哪"、"为什么有讲话声"）——这三条恰恰最可靠，因为它们指向**可修的结构缺陷**而非个人口味。
- **工具侧条件不可完全迁移**：作者用 AI 做量测 + 片段缓存重渲染，才有"一天四版"。我们没有这套缓存，**四版迭代的成本会显著更高**；可迁移的是**量测清单**，不是"一天四版"这个节奏。
- **时代/平台差**：YouTube 横屏 5 分钟精编，非抖音竖屏。**只迁手法，不迁片长与节奏数值**。

## 六、对我们流水线的直接含义

- **立刻可加的两条检查**（成本近零）：
  1. 导出前量**每个切点前后帧的亮度**，接点亮度≈0 的判为闪黑，改硬切；
  2. 导出前查**每条字幕的 out 点是否超出所在片段长度**——本案"海拔 959"就是这样整条不显示的，肉眼看片极难发现。
- **环境音规则改写进流水线**：我们现在的音频轨是"BGM + 环境音 + 旁白"。要加第三类判断：**素材里如果有人说话且与主线无关 → 该段环境音整段静音**，不要"降音量留着"。判据是"这段话在不在字幕里"，工程上可直接用字幕轨反查。
- **逐字稿先行的工序值得试一次**：我们目前是"先排版面，再配旁白"。本案反过来——先挑句子，再画面跟句子。对我们的 VLOG 型素材（含同期声）可能省掉大量返工。
- **海拔剖面图直接进模板**：程序生成 + 节点标记 + "你在这"光晕，比地图动画便宜一个量级，且是观众主动要的东西。可与 11-12 的"英里数播报"合并成同一个"定位层"组件。
- **不要把"四版迭代"设成目标**：那是缓存基建带来的能力。我们的等价物是"**出片后静音看一遍 + 量三个数（切点亮度 / 字幕越界 / 人声段数）**"。
