# 华为云支持服务立项 · 试点成效与证据（美团/顺丰）

**一句话结论：04 号材料是整套立项里说服力最强的一份，但截至 2026-09-21 美团/顺丰双方数据**全部为待补（⬜）**——能立即拿出的唯一硬证据是《管理面数据链路验证报告》；评审的减分点从来不是数字难看，而是只有形容词、没有可复算的数据。**

## 一、为什么这份最硬

立项评审的经典博弈：

- 说"我们**预计**能降低 70% 告警" → 评审问"依据呢" → 答"经验" → **减分**
- 说"美团**实测**告警条数从 X 降到 Y，值班日均被打扰从 A 降到 B" → **加分且难以反驳**

> **结论：能拿数据的，一个都不要用形容词。**

## 二、试点数据统一口径表（12 项）

| 指标 | 口径定义 | 采集方式 |
|---|---|---|
| 试点范围 | 覆盖资源数 / 项目数 | 平台统计 |
| 试点周期 | 起止日期（**至少 4 周**） | — |
| **管理面事件覆盖率** | 已通知的管理面事件 ÷ 平台侧实际发生 | 平台侧比对 |
| **管理面端到端时延** | 平台事件产生 → 客户收到 | 埋点 |
| **告警降噪率** | (原始告警数 − 推送事件数) ÷ 原始告警数 | 平台埋点 |
| **通知准确率** | 推送给正确责任人的比例 | 抽样 + 客户反馈 |
| 端到端时延 | 事件发生 → 客户收到（均值 / P95） | 埋点 |
| **咨询工单下降率** | 试点后 vs 试点前同类工单量 | 工单系统 |
| 值班打扰次数 | 值班人员日均被打扰次数 | 客户反馈 |
| 误报 / 漏报率 | 错误推送 / 应推未推 | 抽样 |
| 客户主观评分 | 1–10 分满意度 | 问卷 / 访谈 |
| **付费意愿** | 愿为 Pro/Enterprise 付费的金额区间 | 访谈直接问 |

**口径纪律（4 条）：**
1. 同一指标**两家客户必须同定义**，否则不能合并陈述；
2. 必须写清**对比基线**（试点前哪段时间、范围是否一致）；
3. **反向指标（误报率）也要写** —— 只写好的数据反而降低可信度；
4. 数据要**可复算**：保留原始导出，评审问"怎么算的"能当场演示。

## 三、试点客户档案（结构，内容待补）

每家一页：客户背景 / 试点动因 / 试点场景 / 关键痛点（客户原话最好）/ 试点成效 / 客户评价 / 后续意向。

- **美团**：头部互联网·本地生活，云资源规模大、多业务线
- **顺丰**：头部物流，业务连续性要求高、**变更敏感**

> 两家当前**均为 ⬜ 待补**，包括最关键的"付费意愿与心理价位"。

## 四、客户证言采集

**争取形式（按价值排序）**：① 书面确认函/盖章邮件（可直接放 PPT）→ ② 访谈录音/纪要 + 签字 → ③ 公开场合口头评价 → ④ **客户参与立项评审做联合发言（杀伤力最大）**。

**访谈照着问：**
- 没有这个产品之前，你们怎么知道云上发生的事？
- 最满意 / 最不满意的一点是什么？
- 如果华为云不做，你们会怎么办（自建 / 换云 / 买第三方）？
- **愿意为这个能力付费吗？付多少？**（直接喂给成本模型）
- 愿意在什么场合对外提到这个试点？

## 五、交付给评审的"硬证据夹"（9 项）

⬜ 《管理面数据链路验证报告》（**新增，优先级最高**）、试点方案书、数据导出原始文件（Excel/CSV）、计算脚本或口径说明、客户访谈纪要（含签字）、客户书面证言、**≥2 个典型 case 复盘**（一个成功降噪、一个群障通知）、界面截图/录屏、客户侧集成截图。

## 六、汇报话术模板（数据填好后套用）

> "**管理面数据通道已完成接入**，覆盖平台运维事件、计划内变更、群障三类，日均 **X 条**，端到端时延 **Y 秒**（P95），与平台侧源数据一致性 **Z%**。在此基础上，美团为期 **X 周**试点覆盖 **Y 项目 / Z 资源**：原始告警 **A 条** → 实际推送 **B 条**，**降噪率 C%**，准确率 **D%**；客户侧同类咨询工单下降 **F%**，值班打扰从 **G 次**降至 **H 次**。顺丰结论一致，**（关键差异点）**。"

> ⚠️ 因为管理面通道已打通，话术**开头第一句就应讲数据链路** —— 先讲"已打通"再讲"效果"，气势完全不同。

> 🔴 **不要编数据。** 哪怕降噪率只有 40% 也比编造的 90% 强 —— 评审席上总有人懂这块，被戳穿一次整份材料就废了。**数字真实 + 趋势正确 + 有价值的定性反馈 = 好材料。**
