# AWS Countdown / IDR / AMS 深度分析 v2 · 新旧模型质量对照与三条实质结论

**一句话结论：用新模型把 09-27（v1 旧模型）对同一批冻结语料的深度分析完整重做，三份报告评级 B/B/C → A/A/B、缺陷总数 21（P0 3）→ 18（P0 0）；最直接的可复用产出不是"写得更长"，而是**新模型主动降低断言强度**的自律行为 —— 但 v2 仍有 1 条 P1 系统性缺陷（`t3` 单来源给 `●` 共 29 处）。**

## 一、新旧质量对照（本轮最直接的产出）

| 报告 | v1 评级（旧模型） | **v2 评级（新模型）** | 变化 |
|---|---|---|---|
| Countdown | B（事实层零可证伪错误） | **A** | ⬆ |
| IDR | B | **A** | ⬆ |
| AMS | **C**（三份最低） | **B** | ⬆ |
| 缺陷总数 | 21（**P0 3** / P1 6 / P2 12） | 18（**P0 0** / P1 4 / P2 14） | **P0 归零** ⬆ |

**v2 三份的共同进步（不是靠"写得更长"）：**

1. **主动撤回 v1 的绝对化表述** —— t1 第 180 行、t2 第 161 行都明确写「『没有任何公开 API』及『无法以任何方式自动化』
   **超出该负向证据的穷尽能力**，本轮撤回 v1 的绝对化表达」。
2. **主动下调置信点** —— t2 把 v1 的**同页重复引用**（同一 URL 被当成两个独立来源）从 `●` 降为 `◐`。
3. **不再补造条件** —— t1 撤回 v1 自行给「2-3 周提前期」补造的适用条件（「准备充分且核验顺利的极简场景」），
   因为来源里根本没有这个分档。
4. **差异标注可对质** —— 审计逐条拿三份的「与 v1 的差异清单」去 v1 原文对质，**未发现一处伪造差异**。

> ⚠️ **采信纪律**：采信 v2 的结论，但**采信它的"收窄版"**，并且**不要引用 t3 的 `●`**（见缺陷 N2/N17）。

## 二、三条最值得拿走的实质结论

1. **🔴 同一份证据，三份报告给出相反的范围判断（审计 N17，编排层复核：成立）**
   t1、t2 都撤回了「AMS/IDR/Countdown 没有任何公开 API」的绝对化表述，**只有 t3 保留并给了 `●`**。
   ⇒ 对外一律采信**收窄版**：「**在本轮检查范围内未发现专属公开 API/CLI 面**」，
   **不能写成「AWS 完全没有」** —— 负向证据的穷尽能力有限。

2. **🔴 Countdown Premium 的 `$10K` 引用必须带促销（审计 N1，复核：成立）**
   `S4-5` 第 3 条明文：「任何『$10K』的引用都必须同时说明促销存在」。
   v2 的 t3 在横向计费对比句中只写了 `$10K`，**漏了促销**（CDP25 $7,500/月、CDP40 $6,000/月，至 2026-12-31 12:00 UTC）
   ⇒ **对外引用时务必带促销口径**。

3. **🔴 AMS 替代路径「自建」的原生组件是 6 个、不是 5 个（审计 N4，复核：成立）**
    Organizations / Control Tower / Systems Manager / Backup / CloudWatch / Security Hub。
