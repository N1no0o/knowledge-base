# 华为云支持服务立项 · 合规、数据与风险

**一句话结论：这个产品的"一票否决区"是数据合规与技术差可改不同 —— 合规出问题直接毙；而风险的**头号位置在立项期内已两次转移**：从"数据拿不到"→"数据质量不足"，并新增了更致命的"内部撞车"。**

## 一、数据合规（最关键）

本产品要采集、处理、存储**客户云上事件与告警数据**，必须回答 7 问：

| 问题 | 设计要求 |
|---|---|
| 数据边界 | 数据留在客户所在 Region，不跨境不越权 |
| 租户隔离 | 租户 ID 强隔离 + 审计（客户 A 绝不可见 B） |
| 采集最小化 | 字段白名单，敏感字段脱敏 |
| 数据留存 | 可配置保留期 + 到期自动销毁 |
| 数据出境 | **优先内部模型，避免数据出境** |
| 客户授权 | 开通协议明确告知 + **可关闭 AI** |
| 导出与删除 | 提供 API |

**法规对标**：网络安全法、数据安全法、个人信息保护法；涉政企/金融另需等保与行业监管。

> ⭐ **建议：明确"AI 处理优先使用华为内部模型服务，客户数据不出华为云"** —— 这一句能挡掉 80% 的合规追问。

## 二、产品自身安全

全链路加密 ｜ 最小权限 + 客户侧角色细分 ｜ **全程可审计**（谁订阅了什么、谁收到了什么）｜ **通知链路自身不能成为故障源**（自己哑火是灾难）｜ 防滥用（频率限制，防止被当骚扰通道）｜ 若依赖第三方情报/模型需评估供应链。

## 三、与现有产品的边界（避免"重复建设"质疑）

| 现有产品 | 它的职责 | 本产品的关系 |
|---|---|---|
| 云监控 | 资源指标监控与告警 | **采集上游**，本产品做统一归集与触达 |
| AOM（应用运维） | 应用层可观测 | **互补**，本产品偏平台侧服务契约 |
| SecMaster（安全云脑） | 安全威胁检测与响应 | **划界**，本文不含安全检测 |
| 工单/客服系统 | 人工服务 | 可联动（P2） |

> **一句话边界声明**："本产品做的是**跨云服务的统一服务事件层**，不替代任何单产品监控能力，而是把它们的信息**统一、增强、精准送达**。"

## 四、风险登记册

| # | 风险 | 等级 | 状态 / 对策要点 |
|---|---|---|---|
| ~~R1~~ | ~~管理面数据拿不到~~ | — | ✅ **已消除** |
| **R0 ⭐** | **内部已在做优护 AI 化/平台化升级（撞车）** | 🔴 **致命** | **10/10 前与优护所属团队对齐**；已在做则转"参与/协同" |
| **R1'** | **管理面数据质量不足**（时延/准确率/覆盖率） | 🔴 高 | 实测 + 校验 + 对齐平台口径 |
| R2 | 跨团队依赖不配合 | 🔴 高 | 高层协调 + 分阶段接入 |
| **R3** | **被质疑与现有产品重复（已加重）** | 🔴 高 | ⚠️ 优护官网**已有同类能力**，须用"平台化 + AI 化增量"正面论证 |
| R4 | AI 误报/漏报损害信任 | 🟡 中 | 分阶段上线，标注置信度 |
| R5 | 成本失控（短信/存储/AI） | 🔴 高 | 配额熔断 + 分级调用 |
| R6 | 数据合规红线 | 🔴 高 | 数据不出境 + 租户隔离 |
| R7 | 试点效果不达预期 | 🟡 中 | 提前对齐验收口径 |
| **R8** | **B 路径下客户对增值包付费意愿不明** | 🟡 中 | 访谈直接问价；用 NPS/工单间接价值兜底 |
| R9 | 通知链路自身故障 | 🟡 中 | 自身高可用 + 多通道路由 |
| R10 | 客户担心信息过载而关闭 | 🟡 中 | 精准路由 + 分级打扰 |
| **R11 ⭐** | **优护是人力密集服务，平台化可能引发内部组织阻力** | 🟡 中 | 明确"**技术增强人、不替代人**"，让服务经理成为受益方 |
| **R12** | **把"IM 通道"当卖点（商业级/企业级已有）** | 🟡 中 | 卖点改锚定"自动化 + AI + 精准路由" |

> **⭐ 风险重心已两次转移：**
> 1. 原 R1（数据拿不到）**已消除** → 转为 R1'（数据质量）
> 2. **新增头号风险 R0：内部撞车** —— 若内部已在推进优护的 AI 化升级，本立项会直接冲突。**这是当前最需要确认的事。**
>
> 同时 **R3 已加重**：因为优护已有同类能力，"重复建设"从"可能被问"变成"**必然被问**"。

## 五、各阶段 Go/No-Go 判据

| 阶段 | 进入下一阶段的判据 | 不达标怎么办 |
|---|---|---|
| 立项 → 需求冻结 | 定位明确(B路径✅) + 数据质量达标 + 立项通过 | 缩小范围重报 |
| 需求冻结 → 试点 | PRD 评审通过 + 资源到位 | 延后 |
| 试点 → Beta | 降噪率≥70%、准确率≥95%、客户认可 | 迭代或止损 |
| Beta → GA | 无 P0 问题、成本达标、**增值包付费意愿明确** | **止损评估** |

> ⭐ **强烈建议在立项书里写明"止损条件"**（例：试点阶段降噪率无法达 50%，或管理面时延无法满足 30 秒 → 终止项目）。
> **主动设止损线反而是加分项** —— 它说明你理性，而不是盲目要资源。
> ⚠️ 注意：原止损条件"管理面数据始终无法获取"**已不适用**（通道已打通），新止损线应聚焦**数据质量**与**客户付费意愿**。
