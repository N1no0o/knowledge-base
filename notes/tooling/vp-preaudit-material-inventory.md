# 开工前素材盘点（preaudit）

**一句话结论：`vp/preaudit.py` 能在约 2 分钟内把一批原片压成「可测事实表 + 人眼待确认清单」，但统计量只能决定"能不能剪"，决定不了"凭什么好看"——亮点、人物、冲突三项必须抽帧实看后才允许写文案。**

## 一、这份报表只写可测事实

- 采样口径：**1 帧 / 15 s**，逐条算时长 / 清晰度 / 曝光（暗部与过曝占比）/ 天空占比 / 植被占比 / 运动量。
- **画面类型一律用本批分位数（p80）判定，不写绝对阈值** —— 阴天 + 秋末素材上绝对阈值会把 27/29 条误判成"其他"（同 [[video-pipeline-action5pro-douyin-automation]] §16.4 第 3 条）。
- 报表里的「需人眼确认」是硬门禁：**未抽帧实看不得写进文案**。
- 性能：29 条 / 204 分钟 / 170.9 GB → **1 分 55 秒**。

## 三、实跑二：smoke1028（联调用小样）

| 项 | 数值 |
|---|---|
| 原片 | **3 条 / 2 分钟 / 0.1 GB**（1920×1080@30，非 4K） |
| 代理 LRF | 0 |
| GPX | **0 ⇒ 海拔/爬升只能口述，不能报数** |
| 类型分布 | 混合/其他 2 · 开阔/天际 1 |

用途是打通 preaudit → 分镜 → 双引擎出片的链路，**不构成可交付内容**（素材无人物、无冲突、无轨迹）。

## 四、人眼待确认清单（五条，每批都跑）

- [ ] 有没有**人**入镜（正脸 / 背影 / 手 / 脚）—— 统计量分不出"队友坐着休息"和"空路"
- [ ] 口述的**亮点**（吃什么、遇到谁、看到什么）是否真的拍到；没拍到要当场告知
- [ ] 画面里的**文字**（路牌、门牌、村名）—— 读出内容须标「疑似，待确认」
- [ ] 有没有可用的**冲突 / 阻力**素材（陡坡、迷路、时间压力、天气）
- [ ] 有没有可用作**结尾长镜**的稳定画面

## 五、判定表：知识库要求 vs 本批素材

| 知识库要求 | hike_1101 | smoke1028 |
|---|---|---|
| 钩子前置且是全片最炸 | 5 条候选，待实看 | 3 条候选，待实看 |
| 必须变速（不许 1.0× 到底） | 可做（0.75×–1.40×） | 可做 |
| 冲突占 40–50% | 待人工确认 | 待人工确认 |
| 时长压到 150–180 s | 可做 | 可做（素材仅 2 分钟） |
| 必须有人物 / 特写 | 待人工确认 | 待人工确认 |

## 六、执行顺序（不许颠倒）

1. 抽帧实看（`--thumbs` 九宫格），把第四节清单全部勾完
2. **只有确认过亮点与画面类型，才允许写 `narration.txt` 或 hitplan**
3. 写文案时逐句对照报表的「画面类型」列，别把路面写成林间

抽帧缓存落在 `video-pipeline/media/cache/preaudit`（按 run id 分目录）。**不要批量删旧缓存**——800 张会触发 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`（50 文件/轮）；靠 run id 隔离，不删旧帧。
