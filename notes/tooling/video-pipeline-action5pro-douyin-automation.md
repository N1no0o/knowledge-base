# 大疆 Osmo Action 5 Pro 徒步素材 · 自动化剪辑与发布方案

**一句话结论：整条链路拆四段，① 素材导入 / ② 自动粗剪 / ③ 配乐旁白前三段可全自动无人值守；第四段「发布抖音」对个人号做不到全自动——抖音官方视频发布能力在开放平台明文要求企业开发者主体，个人账号申请不下来，所有"个人号全自动发抖音"本质都是浏览器/手机端模拟点击，属绕过官方通道且有风控风险。因此第四段只能半自动：脚本上传并填好全部字段，最后一下「发布」人工点。**

- 目标形态：3–5 分钟横屏 Vlog（1920×1080 / 16:9），AI 合成旁白，发布抖音（可同步视频号 / B 站）。

## 一、四段流水线总览

| 段 | 动作 | 自动化程度 |
|---|---|---|
| ① 素材进电脑 | 拔卡 → 读卡器 → 拷入收件箱 → 校验字节数 → 清单 JSON | 半自动（插卡手动，其余自动） |
| ② 自动粗剪 | 场景切分 → 剔废 → 节拍对齐 | **全自动** |
| ③ 配乐与旁白 | LLM 写稿 → edge-tts 配音 → BGM 侧链闪避混音 | **全自动** |
| ④ 发布抖音 | 自动上传 + 自动填标题/话题/封面 → **人工点发布** | 半自动 |

## 二、①素材进电脑

- **推荐：拔 microSD 卡 + USB 3.0 读卡器**。素材在卡上 `DCIM/100MEDIA/`，普通模式 `.MP4`，D-Log M / HLG 专业模式 `.MOV`；USB 3.0 + U3/V30 卡实测可达 **100 MB/s 以上**，数 GB 一两分钟拷完。优先插主板**后置** USB 3.0 口，拔卡前先「安全弹出」。
- 备选：机身 Type-C 直连（需支持 USB 3.0 的线，非原装线可能功率不足连不上）。
- **不推荐无线**：Wi-Fi 6.0 下内置存储最高 80 MB/s、SD 卡最高 50 MB/s，传数 GB 不如拔卡。
- 脚本职责单一：监听盘符出现 → 拷到 `media/inbox/<YYYY-MM-DD>/` → 逐个校验字节数一致 → 记清单 JSON 供下一环节消费。

## 三、②自动粗剪（本方案最需要设计的一段）

> **🔴 关键判断：徒步素材只有风噪、没有人声，网上流行的「静音检测自动剪口播」路线（`auto-editor` 等）对本场景完全无效**——它会把整条片子判成静音段全部剪掉。徒步素材必须走**画面侧**切分。

**三段式粗剪策略：**

1. **切分（按画面而非声音）**：`PySceneDetect` 的 `detect-content` 找镜头边界。徒步素材是连续运动镜头，场景切换通常对应「走到新地形 / 停下拍空镜」⇒ **阈值调高一些**，避免把一次连续运镜切碎。
2. **剔废（先把不能用的干掉）**，任一不达标即剔除：

   | 维度 | 判据 | 目的 |
   |---|---|---|
   | 抖动 | 帧间光流幅度 / 陀螺仪数据（如有） | 剔除手持失控段 |
   | 曝光 | 帧平均亮度落在阈值外 | 剔除过曝、死黑 |
   | 清晰度 | 拉普拉斯方差低于阈值 | 剔除失焦、雨雾糊片 |
   | 静止 | 连续帧差异接近 0 | 剔除支架忘关机的死镜头 |

3. **排序与节拍（决定成片好不好看）**：
   - 基础版（规则）：按拍摄时间轴保留，单段控制在 **3–8 秒**，用 `librosa` 提取 BGM beat 序列，切点向最近节拍吸附（**±0.15s 内**）。
   - 进阶版（语义）：抽关键帧送视觉模型（Qwen2.5-VL / GLM-4V 一类）打分，再由 LLM 按"出发 → 途中 → 爬升 → 登顶 → 远眺"叙事模板排序。**质量提升明显但需额外模型算力与时间，建议列为二期**。

## 四、③配乐与旁白

- **解说稿**：把可结构化信息喂模型——路线名称、起终点、累计爬升/里程（Action 5 Pro 自带气压计，海拔可直接读）、天气、途中见闻与照片时间戳 ⇒ 输出按时间轴分段的解说词。
- **字数口径**：中文 TTS 语速约 **240–300 字/分钟** ⇒ 3–5 分钟成片对应 **800–1500 字**；**别写满**，旁白覆盖 **60%–70%** 时长即可，留画面呼吸空档。
- **配音**：`edge-tts`（微软，免费，无需 API Key）。中文音色：

  | 音色 ID | 性别 | 适用 |
  |---|---|---|
  | `zh-CN-YunjianNeural` | 男·云健 | **运动/纪录片解说感，徒步 Vlog 首选** |
  | `zh-CN-YunxiNeural` | 男·云希 | 活泼口语，轻松向 |
  | `zh-CN-YunyangNeural` | 男·云扬 | 新闻播报，偏正式 |
  | `zh-CN-XiaoxiaoNeural` | 女·晓晓 | 通用女声 |
  | `zh-CN-XiaoyiNeural` | 女·晓伊 | 年轻活泼 |

  TTS 试错成本几乎为零 ⇒ 先用云健试一条，不贴再换。
- **音乐**：优先**抖音平台曲库**（避侵权限流 + 推荐侧天然亲和），次选 Pixabay Music / YouTube Audio Library。
  > 2026-10-15 更新：老板持有**剪映 SVIP**，走剪映路线时音乐版权风险可由 SVIP 曲库直接解除，见 [[jianying-draft-automation-route]]。
- **混音（让 BGM 给人声让路）**：不要简单调低 BGM 音量当背景，用 ffmpeg `sidechaincompress` 做**侧链闪避**——人声一出现 BGM 在 **20ms** 内压下去，人声结束后 **300–400ms** 缓慢恢复。听感上是"专业音轨"而非"音乐盖住说话"。

## 五、④发布抖音（半自动）

- **能力上限**：Playwright 驱动浏览器登录创作者中心 `creator.douyin.com` → 上传成片 → 自动填标题/正文/话题标签/选封面 → **停在发布按钮前人工确认**。
- **为什么停在这一步**：官方发布接口**仅对企业开发者开放**，个人主体申请不下来；无人值守定时发布对个人号不成立；高频机械化操作有风控风险 ⇒ 建议**低频（每天 1–2 条）**且放在人工在线时段。
- 可同步分发视频号、B 站——横屏 3–5 分钟形态在这两个平台的适配度其实**高于**抖音。
- 备选：剪映专业版登录账号后自带「发布到抖音」一键入口，仍需手点，但省掉浏览器自动化。

## 九、风险与已知坑

| 风险 | 说明 | 应对 |
|---|---|---|
| **静音检测路线误用** | 徒步素材无声，`auto-editor` 会把整片判为静音剪光 | 一律走画面侧切分，禁用静音检测 |
| **风噪毁掉现场音** | 运动相机风噪大，现场音多半不可用 | 默认以旁白 + BGM 为主音轨；需现场声先过 `afftdn` 降噪 |
| **剪映版本卡住自动化** | 7.0+ 隐藏导出控件（现为**已知硬边界**）；6.0+ 草稿加密（**10-17 已由社区分支解决**） | 走最新版：草稿自动生成，导出人工点一次；或改云端渲染 |
| **画幅不匹配** | 开 4:3 增稳模式后素材是 4:3 | 统一转制按 16:9 裁切，注意别切掉主体 |
| **抖音自动化风控** | 高频模拟操作可能触发限制 | 低频（每天 1–2 条），人工在场，避免无人值守长跑 |
| **音乐版权** | 外部曲库可能被判侵权限流 | 优先平台曲库（走剪映路线可由 SVIP 解除） |

## 十、附录 · 关键参数与命令

**输出规格（抖音横屏）**：1920×1080 / 30fps / H.264 CRF 19 yuv420p / 音频 AAC 192 kbps / MP4

```bash
# 统一转制到横屏标准（含 4:3 裁切与补边）
ffmpeg -i input.mp4 \
  -vf "scale=1920:1080:force_original_aspect_ratio=decrease,\
pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=30" \
  -c:v libx264 -preset slow -crf 19 -pix_fmt yuv420p \
  -c:a aac -b:a 192k output.mp4

# 场景检测
scenedetect -i input.mp4 detect-content list-scenes

# 旁白配音
edge-tts --voice zh-CN-YunjianNeural --text "今天的路线从这里开始……" --write-media voice.mp3

# BGM 侧链闪避混音
ffmpeg -i video.mp4 -i voice.wav -stream_loop -1 -i bgm.mp3 \
  -filter_complex "[2:a]volume=0.40[bgm];[bgm][1:a]sidechaincompress=threshold=0.03:ratio=8:attack=20:release=400[duck];[1:a]volume=1.0[voice];[voice][duck]amix=inputs=2:duration=first:dropout_transition=0[aout]" \
  -map 0:v -map "[aout]" -c:v copy -c:a aac -b:a 192k output.mp4

# 现场音降噪（需要保留环境声时）
ffmpeg -i input.mp4 -af "afftdn=nf=-25,highpass=f=80" -c:v copy output.mp4
```

## 十二、2026-10-28 实装：方案已落地为 `vp` 包（本页此前的「未安装」状态作废）

**结论：✅ ①②③ 三段全部自动化，④ 发布仍需人工点击，与方案预测一致。** 工程在 `D:/AI/my_project/video-pipeline/`，代码是 Python 包 `vp/`，一条命令出两份剪映草稿。

| 模块 | 职责 |
|---|---|
| `vp/config.py` | 所有可调参数（阈值、时长、音色、分辨率） |
| `vp/srt_parse.py` | DJI `.SRT` 解析（GPS / 海拔） |
| `vp/analyze.py` | 转 480p/10fps 代理 → 场景切分（PySceneDetect）→ 质量筛查 → 打分 |
| `vp/narrate.py` | 旁白稿 + edge-tts 逐段配音（带缓存） |
| `vp/build.py` | 时间轴编排 + 剪映草稿生成（横屏正片 + 竖屏精华） |
| `vp/__main__.py` | 命令行入口 |

```bash
D:\AI\_tools\video-pipeline\.venv313\Scripts\python.exe -m vp \
  --inbox "media/inbox/2026-10-28" --name hike_1028 --bgm "media/bgm/chill.mp3"
```

**九个步骤**：① 转代理（4K 分析提速一个数量级）② 场景切分 ③ 质量筛查（死黑/过曝/糊/静止）④ 打分（清晰度 60% + 曝光 40%，叠加运动强度）⑤ 解析 SRT 算爬升与爬升速率 ⑥ 旁白稿 ⑦ edge-tts 配音 ⑧ 编排 ⑨ 生成草稿。

**「旁白驱动剪辑」的量化口径（这是成片像样的分水岭）**：每段画面时长 = 该句旁白时长 + 留白，留白按覆盖率 **62%** 反推、**上限 2.5 s**；单段画面钳在 **2.5–8 s**；素材不够时循环复用兜底；字幕与旁白同长。

| 调参项（`vp/config.py`） | 默认 | 作用 |
|---|---|---|
| `NARRATION_COVERAGE` | 0.62 | 旁白占比；调大更紧、调小更缓 |
| `MIN_CLIP_SEC` / `MAX_CLIP_SEC` | 2.5 / 8.0 | 单段画面时长区间 |
| `EXPOSE_DARK` / `EXPOSE_BRIGHT` | 18 / 238 | 死黑 / 过曝阈值 |
| `BLUR_LAPLACIAN` | 45 | 清晰度下限（雨雾天可调低） |
| `SHORTS_SEC` | 60 | 竖屏精华目标时长 |
| `VOICE` | 云健 | edge-tts 音色 |

**首跑结果**：3 条原始素材 → 9 段全过筛查，累计爬升 705 m / 最高海拔 1205 m，旁白 44.69 s，产出 `hike_1028_landscape` + `hike_1028_shorts` 两份草稿（剪映 11.6 打开正常）。
